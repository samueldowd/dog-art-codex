# Privacy, costs and retention

Real recordings, native frames, crops, image features and descriptions are processed locally on CT112/Ollama. The primary initially staged four private events on CT112; the user separately authorized protected local copies of those events for visual review after automatic review rejected the initial transfer. Private data stays ignored and excluded from releases. Original attachments and unrelated HA media are preserved.

Default cloud payload: bounded structured appearance description plus the bundled **generated** style reference, sent only through the official OpenAI Python SDK. No real crop, handler frame or full MP4 is sent. Camera upload is rejected by the current loader even if someone flips its flag; a reviewed isolation policy and explicit authority would be needed to implement that expansion. Generated art never enrolls identity.

The single selected dotenv contains nine allowlisted service credentials. Values are not logged, hashed into receipts, copied into general environment, put in argv, or bundled with artifacts. Explicit process secret values may override the selected file, including an empty override; ordinary app/build settings in dotenv fail validation. Credentials in URLs fail. Local file0600; deployed root:dog-art0640. Protect private fixtures/state/backups and model manifests. Exceptions expose categories/codes instead of raw remote bodies.

Official model documentation verified2026-10-22: configured `gpt-image-2.5-sunburst` supports image edits and actual transparent PNG. Standard token prices shown were text input$5/M, image input$8/M and image output$30/M; token consumption depends on the request and is not a fixed per-image price. Sources: [image guide](https://developers.openai.com/api/docs/guides/image-generation), [model](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), [pricing](https://developers.openai.com/api/docs/pricing).

Numeric build cap is$2; ongoing app settings are$5/day,12calls/day, concurrency1, one automatic attempt/portrait. These came from the user-edited files and were normalized to native TOML numbers. Generation stays disabled pending actual acceptance. The build runner must explicitly supply its separate build scope/cap to the shared ledger. Production startup does not read the build file. The explicit OPENAI_PORTRAIT_RESERVATION_USD setting reserves $0.50 per automatic portrait, bounded by the existing $5/day and 12 calls/day caps. This is a conservative planning estimate for the pinned model/size/quality, not measured provider billing or an exact cost guarantee. Missing settings preserve the prior whole-daily-cap reservation. The one controlled build request retains its original $2 reservation; it is never reduced to obtain another build attempt. Preflight budget waits have no ledger row and may wake on the next local day; any existing paid request remains non-resubmittable. Hard call/attempt/concurrency limits supplement estimated dollars. Provider billing can differ from an estimate; use provider project limits as an additional external control.

All reservations/outcomes persist. SDK automatic retries are disabled. Timeout/crash after possible submission means indeterminate; no automatic resubmission. Pre-submission orphan reservations are recovered under the same exclusive barrier used by active senders. Reuse and visual approval cause no paid calls. Do not reset the ledger, remove failed records or fabricate provider idempotency to obtain another attempt.

Permanent identities/references/portraits and historical collages survive midnight/restart. Archive/clip retention settings are recorded, but no automatic retained-artwork/catalog deletion is implemented. The2048MiB free-space guard pauses new media/expensive work rather than deleting retained data. User chose to keep that floor and provide more disk capacity. No host/container allocation changes are implicit.
